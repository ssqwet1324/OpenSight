# Go-сервис OpenSight

HTTP API для локальной Ollama и доставка текста на ESP32 по WebSocket. Модуль: `github.com/ssqwet1324/opensight`.

## Настройка и запуск

Нужна версия Go из `go.mod` или совместимая новее. На проверенном стенде используется `go 1.27.1`.

Из этой папки:

```powershell
Copy-Item .env.example .env
```

Настройки `.env`:

```dotenv
BASE_URL=http://localhost:11434
MODEL=qwen3-vl:2b-instruct
SERVER_PORT=:8080
```

Запусти Ollama и установи выбранную модель. Для первоначальной установки и отдельного запуска, если Ollama ещё не работает:

```powershell
ollama pull qwen3-vl:2b-instruct
ollama serve
```

В другом окне из `lensService`:

```powershell
New-Item -ItemType Directory -Path .local -Force
go build -o .local/opensight.exe ./cmd
.\.local\opensight.exe
```

`SERVER_PORT=:8080` позволяет ESP подключаться по локальной сети. В прошивке указать LAN IPv4-адрес этого компьютера. Если адрес меняется, обновить локальный `opensight-firmware/src/server_config.rs` и перепрошить ESP.

Для Windows предусмотрен скрипт точечного правила брандмауэра: TCP 8080, только программа `.local/opensight.exe` и локальная подсеть. После сборки запустить PowerShell от имени администратора и выполнить, подставив адрес своего компьютера:

```powershell
& .\scripts\allow-lan.ps1 -LocalAddress '192.168.1.100'
```

Проброс портов на роутере не нужен. Сервис предназначен для доверенной локальной сети; аутентификация API здесь не реализована.

## API

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/v1/health` | `OK` |
| POST | `/api/v1/ask` | Вопрос к Ollama, JSON `{"answer":"…"}` |
| GET | `/api/v1/ws` | WebSocket для дисплеев |
| GET | `/api/v1/display/status` | Число WebSocket-клиентов: `{"clients":1}` |
| POST | `/api/v1/display/frame` | Готовый кадр на экран; принимается только с loopback-адреса компьютера |

Отправить вопрос:

```powershell
& .\scripts\ask.ps1 'Объясни простыми словами, как работает Wi-Fi'
```

Либо напрямую:

```powershell
$body = @{ prompt = 'Что такое WebSocket?' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/v1/ask `
  -ContentType 'application/json; charset=utf-8' `
  -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

Сервис получает завершённый ответ Ollama, возвращает его HTTP-клиенту и отправляет на дисплеи. Системный промпт просит краткий ответ на русском, максимум 30 слов. Поток токенов модели не используется; эффект печатной машинки выполняется на OLED.

## WebSocket и экран

- `ws://<адрес-компьютера>:8080/api/v1/ws`.
- Одно обычное UTF-8 сообщение содержит один ответ AI.
- На переподключении отправляется последнее сохранённое сообщение текущего процесса Go. После перезапуска сервиса кэш пуст.
- Медленный клиент получает последнее ожидающее сообщение и не блокирует другие запросы.
- Ограничение текста для дисплея — 4096 UTF-8 байт; при обрезке добавляется многоточие. HTTP-ответ остаётся полным.
- Ping каждые 20 секунд; ESP отвечает pong и переподключается при потере связи.
- Служебный префикс `\x1eOSF1 ` зарезервирован для текстового кадра.

Внешний локальный источник может отправить `application/json` на `/api/v1/display/frame`:

```json
{"rows":["Привет!","","","","",""],"positionMs":6000}
```

Нужны ровно шесть строк, каждая до 21 символа. `positionMs` — целое неотрицательное время до 86400000 мс. Go передаёт их в WebSocket как `\x1eOSF1 6000\n…`. Ответ `204` означает принятие кадра сервисом; это не подтверждение физической отрисовки дисплеем. Полный кадр позволяет корректно обрабатывать паузу, перемотку и пропущенные промежуточные обновления.

Чтобы увидеть обычный ответ AI во время работы внешнего источника, сначала остановить отправку кадров. На проверенном OLED русский текст выводится по буквам с переносом слов и прокруткой.

## Проверки

```powershell
go test ./...
```

Проверяются HTTP JSON, доставка ответа, ошибки запросов, replay после переподключения, медленные клиенты, ограничение UTF-8 и валидация кадров.
